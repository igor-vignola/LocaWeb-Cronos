Cronos Design System · 02

Motion.
O sentimento.

Motion é como cada elemento se move na tela. Botão respondendo ao toque, card entrando, tooltip abrindo, toggle flipando. Não é decoração — é o feedback que diz pro usuário "sua ação foi recebida". Tudo abaixo é interativo. Clica, passa o mouse, segura.

01

3 princípios

Apple HIG aplicado ao Cronos. Toda decisão de animação responde a estas perguntas antes de existir.

PROPÓSITO

Anime com motivo

Animação gratuita distrai. Se você não consegue explicar pra que serve, não anime. Bom: dar feedback de press. Ruim: animar tudo só pra "parecer dinâmico".

BREVIDADE

Curto e preciso

Animação em UI dura abaixo de 300ms. Um botão press é 140ms. Tooltip 200ms. Se o usuário precisa esperar a animação acabar, ela é longa demais.

RESPEITO

Motion é opcional

Alguns usuários têm sensibilidade a movimento (vestibular, enxaqueca). Respeitamos prefers-reduced-motion em tudo — animações viram instantâneas, opacidade preservada.

02

Easing curves

Cada curva tem uma "personalidade". Clica em Disparar corrida pra ver as 5 bolinhas correndo lado a lado — você sente a diferença.

As 5 bolinhas correm a mesma distância, mesmo tempo (1200ms), com easings diferentes.
ease-out cubic-bezier(0.25, 1, 0.5, 1)
UI default
ease-out-strong cubic-bezier(0.16, 1, 0.3, 1)
Enter anim
ease-in-out cubic-bezier(0.76, 0, 0.24, 1)
On-screen
ease-drawer cubic-bezier(0.32, 0.72, 0, 1)
iOS drawer
ease-spring cubic-bezier(0.34, 1.56, 0.64, 1)
Overshoot
Como interpretar: ease-out e ease-out-strong partem rápidas e desaceleram — feeling "snappy", perfeito pra entradas e hovers. ease-in-out acelera e desacelera — natural pra movimento on-screen. ease-spring ultrapassa o destino e volta — efeito "boing", reservado pra toggles e gestos. Built-in CSS (ease, ease-out CSS) é fraco demais — sempre use as 5 curves customizadas.
03

Durations

Quanto tempo cada animação dura. Cada token tem um caso de uso bem definido — não improvise.

80ms
--dur-instant
Mudança de cor/borda em hover
140ms
--dur-fast
Press de botão (scale 0.97)
200ms
--dur-quick
Hover lift · tooltip enter
280ms
--dur-base
Card enter · panel transition
400ms
--dur-slow
Modal abrindo · drawer slide
Regra prática: se o usuário interage (press, hover), use --dur-fast ou --dur-quick. Se o sistema reage (card aparecendo, panel entrando), --dur-base. Se um contexto muda (modal abre, drawer desliza), --dur-slow. Acima de 400ms = lento demais pra UI.

06

Reduced motion

Acessibilidade não-negociável. Alguns usuários ativam "Reduce motion" no sistema operacional — temos que respeitar.

Como ativar pra testar

macOS: System Settings → Accessibility → Display → Reduce motion
iOS: Settings → Accessibility → Motion → Reduce motion
Windows: Settings → Accessibility → Visual effects → Animation effects (off)

O sistema operacional propaga o setting via media query.

Como respeitamos no Cronos

Toda animação no tokens.css é wrapped em @media (prefers-reduced-motion: reduce). Quando ativo:

• Animations viram 0.01ms (instantâneas)
• Transitions viram 0.01ms
• Pulses e loops infinitos param
• Opacity preservada (não é movimento)
• Smooth scroll desativado

Já tá implementado. Veja em assets/tokens.css o bloco @media (prefers-reduced-motion: reduce) no final do arquivo. Aplica globalmente em tudo que usar transitions ou animations CSS.
