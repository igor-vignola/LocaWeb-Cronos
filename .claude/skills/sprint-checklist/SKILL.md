# Sprint Checklist — Challenge FIAP 2026 Locaweb

## Como usar este checklist

**REGRA ABSOLUTA:** Antes de finalizar QUALQUER entregável, percorra o checklist da sprint correspondente item por item. Se algum item não foi atendido, avise o Igor e não finalize até resolver.

**REGRA DE QUALIDADE:** Cada item deve ser verificável — não basta "ter mencionado", precisa ter sido bem feito.

**REGRA DE FORMATO:**
- Todos os PPTs devem ser .pptx (PowerPoint fonte, não PDF)
- Nome do arquivo segue o padrão: EC_Sprint_X_2TSCOA_[tipo]_[nome_projeto]_[nome_grupo].pptx
- RMs e nomes SEMPRE em ordem alfabética
- Arquivos devem funcionar preferencialmente no Windows

## Sprint 1 — Ideação (entrega: 27/04/2026)

**Arquivo:** EC_Sprint_1_2TSCOA_ideacaoprojeto_[nome_projeto]_[nome_grupo].pptx

### Checklist de conteúdo obrigatório

- [ ] **1. Identificação do grupo**
  - Turma (2TSCOA)
  - RM de cada aluno
  - Nome completo de cada aluno
  - Nomes em ordem alfabética

- [ ] **2. Nome do projeto**
  - Nome definido, envolvente e memorável
  - Transmite a essência da solução

- [ ] **3. Contextualização do problema**
  - Explica o cenário da Locaweb (operação 24x7, ITSM)
  - Menciona o desafio AIOps
  - Dá contexto suficiente para quem não conhece o tema

- [ ] **4. Problema a ser resolvido**
  - Define CLARAMENTE o problema principal
  - Apresenta dados ou casos de uso que evidenciem a importância
  - Usa dados reais do dataset quando possível (122k incidentes, KPIs, etc.)

- [ ] **5. Público-alvo**
  - Identifica QUEM vai usar a solução
  - Especifica perfil (técnico, negócio, ou ambos)

- [ ] **6. Proposta de solução**
  - Apresenta a ideia de forma clara e concisa
  - Destaca os principais benefícios
  - Explica COMO resolve o problema identificado

- [ ] **7. Impacto da solução**
  - Identifica impacto para stakeholders específicos
  - Destaca ONDE e COMO a proposta faz diferença

- [ ] **8. Benefícios esperados**
  - Lista resultados positivos esperados
  - Comunica POR QUE a solução é valiosa

- [ ] **9. Comparativo com concorrência**
  - Identifica concorrentes/similares no mercado
  - Mostra oportunidades de diferenciação
  - Explica por que a solução proposta é melhor ou diferente

### Verificação de qualidade Sprint 1
- [ ] Slides são visualmente limpos e profissionais?
- [ ] Linguagem é clara (sem jargões sem explicação)?
- [ ] Há coerência entre problema → solução → benefícios?
- [ ] O PPT conta uma "história" que faz sentido do início ao fim?

## Sprint 2 — Arquitetura (entrega: 24/05/2026)

**Arquivo:** EC_Sprint_2_2TSCOA_arqsolucao_[nome_projeto]_[nome_grupo].pptx

### Checklist de conteúdo obrigatório

- [ ] **1. Problema + público-alvo + proposta ATUALIZADOS**
  - Reapresenta o que foi entregue na Sprint 1
  - Indica se houve QUALQUER alteração desde a Sprint 1
  - Documenta o que mudou e por quê

- [ ] **2. Arquitetura e desenho inicial da solução**
  - DESENHO VISUAL da arquitetura (obrigatório, mesmo preliminar)
  - Delineia tecnologias empregadas
  - Mostra conexões entre componentes
  - Indica se cloud ou on-premise
  - Detalha o PAPEL de cada tecnologia

- [ ] **3. Descrição da arquitetura (tecnologias)**
  - Lista todas as ferramentas e plataformas
  - Explica o papel de cada uma na solução
  - Entendimento claro e compartilhado

- [ ] **4. Protótipos da solução**
  - Protótipos visuais (wireframes, mockups, telas)
  - Breve descrição do significado de CADA protótipo
  - Permite identificar riscos precocemente

- [ ] **5. Análise Exploratória de Dados (EDA)**
  - Padrões identificados no dataset
  - Oportunidades encontradas
  - Desafios previstos para próximas etapas
  - Gráficos e visualizações dos dados

- [ ] **6. Gerenciamento ágil do projeto**
  - Framework ágil definido (Scrum sugerido, mas livre)
  - Cronograma de atividades
  - Divisão de tarefas entre membros
  - Evidências de uso de ferramentas de gestão (Trello, Jira, etc.)

- [ ] **7. Finalização e agradecimentos**
  - Conclusão do que foi apresentado
  - Agradecimentos

### Verificação de qualidade Sprint 2
- [ ] O desenho da arquitetura está claro e legível?
- [ ] Cada tecnologia tem justificativa para estar ali?
- [ ] Os protótipos são suficientes para visualizar a solução?
- [ ] A EDA mostra insights reais do dataset (não genéricos)?
- [ ] O gerenciamento ágil é realista para o tamanho do grupo?

## Sprint 3 — MVP Preliminar (entrega: 23/08/2026)

**Arquivo:** EC_Sprint_3_2TSCOA_Evidencias_Construcao_[nome_projeto]_[nome_grupo].pptx

### Checklist de conteúdo obrigatório

- [ ] **1. Contextualização + problema + solução (ATUALIZADOS)**
  - Resumo do escopo do projeto
  - Informa qualquer mudança desde a Sprint 2

- [ ] **2. Gerenciamento de projetos ATUALIZADO**
  - Documenta o que foi planejado vs executado (Sprints 1 e 2)
  - Atualiza cronograma e divisão de tarefas
  - Anexa documentação das sprints anteriores

- [ ] **3. Arquitetura + descrição (ATUALIZADA)**
  - Desenho da arquitetura (OBRIGATÓRIO, mesmo sem mudanças)
  - Descrição das tecnologias utilizadas
  - Indicar mudanças desde a Sprint 2

- [ ] **4. MVP funcional com evidências**
  - Versão preliminar FUNCIONAL da solução
  - Código-fonte efetivo (não só planejamento)
  - Evidências visuais: screenshots, prints, gráficos gerados
  - Resultados de modelos (métricas, previsões)
  - Valida na prática os principais recursos propostos

- [ ] **5. Finalização e agradecimentos**

### Verificação de qualidade Sprint 3
- [ ] O MVP realmente FUNCIONA (não é só mockup)?
- [ ] Há código-fonte real sendo mostrado?
- [ ] As evidências são convincentes?
- [ ] Os modelos preditivos estão produzindo resultados?
- [ ] Está claro o progresso desde a Sprint 2?

## Sprint 4 — Solução Final (entrega: 08/09/2026)

### Entregáveis múltiplos

#### a) Planilha de catalogação
- [ ] Informacoes_Finais_Projeto_Integrantes_v1.xlsx preenchida
  - Nome da equipe
  - Nome do projeto

#### b) PPT Final
**Arquivo:** EC_Sprint_4_2TSCOA_solucaofinal_[nome_projeto]_[nome_grupo].pptx

- [ ] **Contextualização do desafio** — problema enfrentado
- [ ] **Objetivo do projeto** — o que se buscou alcançar
- [ ] **Proposta de solução** — abordagem, etapas, tecnologia, arquitetura, fontes de dados, análises, indicadores
- [ ] **Demonstração da solução funcionando** — LINK da aplicação (Power BI, dashboard, relatório)
- [ ] **Benefícios gerados** — impactos esperados ou já obtidos
- [ ] **Conclusão e próximos passos** — aprendizados, limitações, evoluções possíveis

#### c) Vídeo Pitch
- [ ] Duração máxima: 5 minutos
- [ ] Formato hands-on (mostrando a solução funcionando)
- [ ] Upload no YouTube (acesso público)
- [ ] Link dentro do PPT
- [ ] Estrutura sugerida:
  - Abertura + contextualização (≈30s)
  - Objetivo do projeto (≈30s)
  - Proposta de solução (≈1min)
  - Demonstração funcionando (≈2min)
  - Benefícios gerados (≈30s)
  - Conclusão + próximos passos (≈30s)

#### d) Arquivo ZIP final
**Arquivo:** EC_Sprint_4_2TSCOA_solucaofinal_[nome_projeto]_[nome_grupo].zip

- [ ] Todos os códigos-fonte (TODOS, mesmo os não solicitados)
- [ ] Imagens utilizadas
- [ ] Arquivos Excel e dados tratados
- [ ] Diagramas e dashboards
- [ ] PPT final
- [ ] Arquivo .TXT separado com:
  - Link do vídeo pitch (YouTube público)
  - Nome da equipe
  - RMs e nomes em ordem alfabética

### Verificação de qualidade Sprint 4
- [ ] A solução está FUNCIONANDO com link acessível?
- [ ] O vídeo pitch tem ≤5 minutos?
- [ ] O link do YouTube é público (qualquer pessoa acessa)?
- [ ] O .zip contém TODOS os materiais?
- [ ] Código-fonte está organizado e comentado?
- [ ] O PPT reflete a jornada coerente das Sprints 1-3?
- [ ] A planilha Excel está preenchida corretamente?

## Verificação cruzada final (antes de qualquer entrega)

1. **Nome do arquivo** segue o padrão correto?
2. **RMs e nomes** estão em ordem alfabética?
3. **Formato** é .pptx (não .pdf, não link)?
4. **Conteúdo** cobre TODOS os itens listados acima?
5. **Evolução** — o material mostra progresso em relação à sprint anterior?
6. **Coerência** — problema → solução → resultados fazem sentido juntos?
7. **Dados reais** — usou dados do dataset (não inventou números)?
8. **Linguagem** — está clara para público técnico E de negócio?
